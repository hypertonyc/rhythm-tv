# CLAUDE.md

Rhythm TV — клиент медиасервера для Samsung Smart TV на Tizen 2.3 (телевизоры 2015 года).
Пользовательское описание в [README.md](README.md); здесь то, что нужно знать перед правкой кода.

## Главные ограничения

**`js/app.js` — строго ES5.** WRT на Tizen 2.3 не понимает `let`/`const`, стрелочные функции,
шаблонные строки, `Promise`, `async`/`await`, `fetch`, деструктуризацию, `Array.prototype.includes`.
Только `var`, `function`, `XMLHttpRequest`, колбэки. Это не стилевое предпочтение — код просто
не запустится. Предупреждение стоит в шапке файла.

**Никакой сборки.** Нет npm, package.json, бандлера, транспайлера, тестов, линтера. Проект —
это набор статических файлов, который упаковывается в `.wgt`. Не предлагать TypeScript,
модули ES, зависимости из npm.

**Новый файл надо вписать в `files:` в `tizen_web_project.yaml`,** иначе он не попадёт
в пакет, и приложение на телевизоре молча сломается. Задача сборки проверяет наличие
`js/app.js` и `js/config.js` в готовом `.wgt` именно из-за этой грабли.

**На телевизоре нет консоли.** Отладка только через экран: `window.onerror` пишет в красный
блок `#fatal`, для сообщений по ходу работы есть `showHud()` в плеере и `setStatus()` в меню.

## Как устроен app.js

Один IIFE, состояние в переменных модуля. Экран определяется переменной `mode`
(`'boot'` → `'setup'` / `'menu'` / `'player'`), переключение — присваиванием `className`
контейнерам из `index.html`. Вся навигация с пульта в `handleKey()`, коды кнопок
берутся через `tizen.tvinputdevice.getKey()` с числовыми фолбэками.

Неочевидные решения, которые выглядят как мусор, но нужны:

- **`guardedRequest()`** — обёртка над XHR со сторожевым таймером. На этом WRT запрос,
  отклонённый WARP, может не вызвать ни `onerror`, ни `ontimeout`, и колбэк не придёт никогда.
- **Тройной запуск `bootOnce()`** — `DOMContentLoaded`, `window.onload` и `setTimeout` на 2 с.
  `window.onload` срабатывает не на всех сборках Tizen, если в документе есть объект avplayer.
  Флаг `booted` защищает от повторного входа.
- **Субтитры рисуются на `<canvas>`,** а не отдаются AVPlay. Текст берётся из отдельного
  VTT-плейлиста, который опрашивается по XHR раз в 1200 мс (`pollSubtitlePlaylist`),
  парсится вручную (`parseVtt`) и выводится в `drawSubtitle`. Через TEXT-трек AVPlay
  на старом компоновщике субтитры не показывались — путь с треком уже пробовали и убрали.
- **Перемотки как таковой нет.** `seekRelative()` закрывает AVPlay и заново запускает HLS
  с сервера с новым `start=`. `avplay.seekTo` на этой прошивке ненадёжен.
- **Пустые `onevent`/`onsubtitlechange`** в листенере AVPlay оставлены сознательно —
  на старых прошивках неполный объект листенера приводит к ошибкам.

## Адрес сервера

В коде адрес не хардкодится. `DEFAULT_SERVER` лежит в `.env`, задача сборки генерирует
из него `js/config.js` с `window.RTV_CONFIG.defaultServer`, а `app.js` читает оттуда
с фолбэком на пустую строку (пустая = откроется экран настройки). `js/config.js` в
`.gitignore`, потому что адрес содержит приватный токен в пути.

Сохранённый пользователем адрес в `localStorage` (`rtv.server`) имеет приоритет над
запечённым — если меняли адрес на телевизоре, новая сборка сама его не подхватит.

Ключи в localStorage: `rtv.server`, `rtv.positions` (JSON: индекс файла → секунды),
`rtv.lastEpisode`, `rtv.audio`, `rtv.sub`, `rtv.autonext`, `rtv.subtitleSize`.

## API сервера

Сервер в этом репозитории отсутствует. Клиент ожидает: `/api/files`, `/api/probe/:index`,
`/api/start/:index?audio=&sub=&start=`, `/api/hls-status/:id`, `/api/prebuffer/:index`,
`/api/status`, `/api/stop`. Играть начинаем, когда `/api/hls-status` отдаёт ≥2 стартовых
сегмента или `state === 'finished'`.

## Сборка

Задача `Tizen: Build & Install on TV` в `.vscode/tasks.json` — один длинный shell-однострочник
внутри JSON, все кавычки экранированы. Правится аккуратно, после правки проверять
валидность JSON. Порядок: проверка `.env` → генерация `js/config.js` → `sdb connect` →
`rm -rf Debug/` → `tz build` → `tz pack` → проверки содержимого `.wgt` → `tizen install`.

`Debug/` — целиком результат сборки, пересоздаётся каждый раз, в `.gitignore`.
Версия приложения живёт в `config.xml` (атрибут `version` у `<widget>`).

## Окружение

`node` и `npm` в системе не установлены. Синтаксис JS можно проверить через JavaScriptCore:

```sh
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc \
  -e "new Function(readFile('js/app.js')); print('OK')"
```

Полную сборку без подключённого телевизора прогнать нельзя — задача падает на проверке
`sdb devices`.

## Открытые вопросы

- `waitForHls()` опрашивает сервер каждые 700 мс без предела попыток: если сегменты
  так и не появятся, опрос будет идти бесконечно.
- Токен из `DEFAULT_SERVER` остался в истории git (коммиты до `4ca3155`) — `.gitignore`
  это не отменяет.
