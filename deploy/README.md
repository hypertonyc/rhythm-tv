# Деплой

Сервер живёт на Маке в домашней сети, телевизор ходит к нему по `http://<HOME_IP>:8000`. Всё, что для этого
нужно, — в `deploy/mac/`; рабочая копия на Маке — `~/rhythm-tv/deploy/`, туда её кладёт `install.sh`.

CI (`.github/workflows/server.yml`) только гоняет тесты и кладёт образ `linux/amd64` в GHCR — выкатки нет.
До 19.11.2026 сервер жил на VPS и выкатывался из CI; тот путь снят вместе с VPS, его история — в git.

## Установка

```sh
mkdir -p ~/rhythm-tv/deploy && cp deploy/mac/.env.example ~/rhythm-tv/deploy/.env
docker build -t rhythm-tv/server:$(git rev-parse --short=7 HEAD) server
deploy/mac/install.sh
~/rhythm-tv/deploy/check-egress.sh
```

Между первой и третьей строкой — заполнить `.env`: каталоги, `SERVER_TAG` (тот же тег, что у сборки),
`HOME_IP`, `HOME_DHCP_MARK` (серийный номер роутера — ASCII-колонка дампа `option_125` в `ipconfig getpacket en0`,
разрезанная переносом строки). `install.sh` повторять безопасно: он перекладывает файлы, перезапускает агент
launchd и делает `docker compose up -d`.

Образ собирается на самом Маке штатным Dockerfile (arm64). Пока поднят рабочий VPN, `go mod download` внутри
сборки может не дойти до прокси модулей — собирать с выключенным.

Роутеру — DHCP-резерв на `HOME_IP`, Маку — «Частный адрес Wi-Fi: Фиксированный» для домашней сети: иначе адрес
уйдёт, сервер решит, что он не дома, и телевизор его не увидит.

## Обновление и откат

```sh
docker build -t rhythm-tv/server:$(git rev-parse --short=7 HEAD) server
cd ~/rhythm-tv/deploy && docker compose up -d
```

Между ними — новый `SERVER_TAG` в `~/rhythm-tv/deploy/.env`. Откат — прежний тег туда же и `docker compose up -d`,
поэтому старые образы `rhythm-tv/server:*` не чистить, пока новый не проверен на телевизоре. Перезапуск
посреди серии допустим: каталог сеанса переживает его и подбирается новым процессом (`hls/adopt.go`).

## Устройство и почему так

- **Торрент не ходит через VPN Мака.** Docker Desktop выпускает трафик контейнеров через процесс на Маке, то есть
  по таблице маршрутов Мака — при поднятом VPN в туннель. Поэтому у сервера нет своей сети: он живёт в сетевом
  пространстве `tms-egress` (sing-box), где всё, кроме ответов на опубликованный порт, уходит в `tun0`, а оттуда —
  SOCKS5 с UDP-over-TCP на реле `127.0.0.1:1088` на Маке. Реле (`relay.json`) открывает соединения с привязкой
  к `en0` (`IP_BOUND_IF`): такая привязка сильнее маршрутов VPN, а под VPN, который снимает маршрут через `en0`,
  соединения не уходят в туннель, а не устанавливаются вовсе — пока VPN поднят, сервер не качает, скачанное
  играет. DNS — тоже через реле (1.1.1.1 по TCP); частные адреса и мультикаст из контейнера отрезаны, поэтому
  UPnP до роутера не доходит. Нет реле — у сервера нет выхода наружу совсем. Проверка — `check-egress.sh`
  (сравнивает адрес сервера с адресом `en0` и показывает потоки реле по интерфейсам через `nettop`).
- **Порт в LAN отдаёт не Docker.** Docker.app в файрволе macOS закрыт на входящие (порты чужих compose на `0.0.0.0`
  не должны торчать в сеть), поэтому Docker публикует сервер только на `127.0.0.1:8000`, а на `HOME_IP:8000`
  слушает `lanproxy.py` под `/usr/bin/python3` — подписан Apple, файрвол пропускает его сам. Авторизации у
  сервера нет вовсе, поэтому снаружи домашней сети его быть не должно.
- **Реле и `lanproxy.py` работают только дома.** Их держит агент launchd `local.rhythm-tv.homegate`
  (`homegate.sh`): дом — это `HOME_IP` на `en0` и серийный номер роутера в DHCP option 125 (`HOME_DHCP_MARK`;
  ARP и SSID macOS непривилегированным не показывает). В чужой сети через 30 с оба гаснут: сервер не виден
  и ничего не качает. Лог — `~/rhythm-tv/logs/homegate.log`.
- **Перезапуск `tms-egress` оставляет сервер без сети** (у него остаётся только `lo`) — Docker не переподключает
  чужое сетевое пространство. `homegate.sh` замечает, что сервер запущен раньше egress, и перезапускает его.
- **Свободное место на bind mount меряется в `f_frsize`.** У virtiofs Docker Desktop `f_bsize` = 1 МиБ при
  `f_frsize` = 4 КиБ, и по `Bsize` чистка видела в 256 раз больше места, чем есть (`statfs_linux.go`).

## Где лежат данные

- `TORRENT_DIR` (`~/rhythm-tv/data`) — `.torrent`, `.tms-active`, журнал просмотров `.tms-watched`, обычные
  скорости перекодирования `.tms-rates`, паки субтитров `subs/`. Маленький, идёт в Time Machine.
- `STORE_DIR` и `HLS_DIR` — скачанное и сегменты. Их место — отдельный том APFS с квотой, исключённый из Time
  Machine: на системном томе удалённое держат локальные снимки до суток, и чистка, не видя освободившегося места,
  выселяла бы ещё и ещё. Такой том надо **явно** добавить в Docker Desktop → Settings → Resources → File sharing:
  строка `/Volumes` его не покрывает (внутри VM он виден как `host-mount-point-outside-of-authorized-share`),
  а вложенный путь при ней интерфейс не добавляет — её приходится заменить. Исключить том из Time Machine
  из терминала можно только с Full Disk Access; проще в Системных настройках → Time Machine → Параметры.

## Паки субтитров

Пак кладётся каталогом в `subs/` библиотеки; сервер перечитывает его раз в полминуты сам, перезапуск не нужен
(кроме уже открытых серий — их разбор кэшируется навсегда).

```sh
mkdir -p ~/rhythm-tv/data/subs && cp -R ПАК ~/rhythm-tv/data/subs/
```

`ПАК` — путь к каталогу пака.

Права менять не надо: Docker Desktop отдаёт файлы Мака контейнеру под его uid сам. Имя каталога пака стоит
оставлять говорящим (`…_rus_…`, `rus/`, `Russian/`): по нему сервер определяет язык дорожки.

## Место на диске

Скачанное сервер чистит сам: раз в минуту он смотрит на свободное место в `STORE_DIR` и, если его меньше
`STORE_MIN_FREE_GB` (20), выселяет серии — начиная с тех, которые дольше всех не смотрели, — пока не станет
`STORE_TARGET_FREE_GB` (30). Выселенное не потеряно: куски докачаются, когда серию снова захотят посмотреть.
Свободное место и итог чистки видны и с телефона — строкой в панели библиотеки на странице сервера.

```sh
docker logs tms-server 2>&1 | grep 'чистка места'
cat ~/rhythm-tv/data/.tms-watched
curl -s 127.0.0.1:8000/api/torrents | head -c 300
```

Выключить (например, чтобы разобраться, куда делось место) — `STORE_MIN_FREE_GB=0` в `~/rhythm-tv/deploy/.env`
и `docker compose up -d`.

Каталог сегментов HLS не ограничен по размеру by design — счётчик идёт вверх, старые `.ts` не удаляются до конца
сеанса, и чистка места его не трогает: она умеет выселять только скачанное торрентами. Запас в пороге (20 ГБ)
рассчитан и на него.
